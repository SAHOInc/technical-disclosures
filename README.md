## Publishing / 发布 / 公開

Public article → GitHub Release → verified Zenodo archive and DOI → optional announcement.

公开文章 → GitHub Release → 核实 Zenodo 归档与 DOI → 可选公开公告。

公開記事 → GitHub Release → Zenodo アーカイブと DOI の確認 → 任意の公開告知。

Each Release archives the whole repository snapshot. A shared snapshot DOI does not identify each article independently. Public commits are already visible; prepare unfinished or confidential material outside this public repository.

每次 Release 归档整个仓库快照，共享的快照 DOI 不等于每篇文章独立的 DOI。公开提交即可被访问；未完成或保密材料应在本公开仓库之外准备。

Release ごとにリポジトリ全体を保存します。共通の DOI は記事単体の独立した DOI ではありません。公開コミットは閲覧可能なため、未完成・機密の資料は別の場所で準備してください。

## Organization / 目录 / 構成

Topic folders are created when articles are ready, for example speech translation or proximity verification. Folder names and examples alone do not describe an implementation.

文章准备好后再创建主题目录，例如语音翻译或近距离验证。目录名称和示例本身不构成实现说明。

記事の準備が整い次第、音声翻訳や近接検証などの分野別フォルダーを作成します。名称や例示のみでは実装を説明したことにはなりません。
